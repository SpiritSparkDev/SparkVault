# S3 Target Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add S3-compatible object storage (AWS S3 and S3-compatible providers like MinIO, Backblaze B2, Hetzner, Wasabi via a custom endpoint) as a fourth backup target type, alongside the existing Local/FTP/SFTP targets.

**Architecture:** `S3Target` implements the existing `IBackupTarget` interface via `AWSSDK.S3`, reusing every piece of infrastructure the FTP/SFTP targets already established: `CredentialProtector` for encrypting the secret key, `TargetFactory` for dispatch, `BackupTargetRepository`/`JobRepository` for persistence, and `TargetEditorWindow`'s per-type-panel UI pattern. Unlike FTP/SFTP, S3's `PutObject` is already atomic (an aborted request never makes a partial object visible), so `S3Target` uploads directly to the final key and verifies via `HeadObject` — no temp-key-then-rename dance needed.

**Tech Stack:** .NET 8, `AWSSDK.S3` 4.0.102.3, `minio/minio` Docker image for integration testing. Every AWSSDK.S3 API call in this plan was verified by the plan's author against the real installed package, including a live round-trip (bucket create, PutObject, HeadObject verify, ListObjectsV2, DeleteObject, confirm-deleted via 404) against a real running MinIO container.

**Spec:** [docs/superpowers/specs/2026-08-21-s3-target-design.md](../specs/2026-08-21-s3-target-design.md)

**Prior work:** [docs/superpowers/plans/2026-08-20-ftp-sftp-targets.md](2026-08-20-ftp-sftp-targets.md) — the FTP/SFTP plan this one builds on, already merged into `feature/mvp`. Read the actual current state of the files this plan touches before editing (`git log`/the files themselves), not just this plan's text — several files (`BackupTargetExtensions.cs`, `TargetEditorWindow.xaml.cs`) already reflect fixes from that plan's own final review.

## Global Constraints

- .NET 8, C#. Exact package version: `AWSSDK.S3` 4.0.102.3 — checked advisory-free by the plan's author, use exactly this version.
- Strict 0-warnings build convention, unchanged from the FTP/SFTP plan.
- S3 uploads are direct-to-final-key + `HeadObject` size verification — NOT the temp-name-then-rename pattern `LocalTarget`/`FtpTarget`/`SftpTarget` use. This is a deliberate, spec-approved deviation: S3's `PutObject` is already atomic, so replicating the temp-file dance would be pure overhead for a guarantee S3 already provides.
- `ForcePathStyle` on the S3 client config is tied to whether a custom `Endpoint` is set: `true` when set (S3-compatible providers generally require path-style requests), `false`/default when empty (real AWS S3, virtual-hosted-style). Verified against a real MinIO container with `ForcePathStyle = true`.
- `BackupTargetExtensions.Describe()` (in `src/SparkVault.Core/BackupTargetExtensions.cs`) has a deliberately exhaustive switch with NO default arm — adding `TargetType.S3` to the enum without adding a case here is a compile error (CS8509) by design. Task 2 below adds both the enum member and the `Describe()` case in the same task, so `SparkVault.Core` never has an interim broken-build state the way the FTP/SFTP plan's `BackupJob.DestinationPath` removal did — there is no bridge needed this time, keep it that way.
- Region is a required UI field even for providers that don't meaningfully use AWS regions (a placeholder value like `"us-east-1"` is fine) — this matches what the plan's author verified works against MinIO.
- `Prefix` reuses the existing generic `BackupTarget.RemotePath` column/property — no new column for it. It's the S3 equivalent of what `RemotePath` already means for FTP/SFTP (a destination-relative subfolder).
- Remote (S3 key) paths use forward slashes always; `BackupFile.RelativePath` (Windows-style) must be normalized before use — plain string concatenation only, never `Path.*`. Same rule as `FtpTarget`/`SftpTarget`.
- Docker integration tests (`S3TargetTests`) must not fail the build when Docker isn't running — same `DockerTestHelper.IsReachable` early-return pattern already established.
- No database migration framework — schema changes are `CREATE TABLE IF NOT EXISTS`, not backward-compatible with an existing dev-machine `sparkvault.db`. Task 8's manual verification must delete that file first, same as the FTP/SFTP plan required.
- App title stays **SparkVault**.

```csharp
using Amazon.S3;
using Amazon.S3.Model;

namespace SparkVault.Core;

public sealed class S3Target : IBackupTarget
{
    private readonly string _bucket;
    private readonly string _prefix;
    private readonly AmazonS3Client _client;

    public S3Target(BackupTarget config)
    {
        _bucket = config.Bucket ?? throw new InvalidOperationException("S3 target requires Bucket.");
        _prefix = config.RemotePath ?? "";
        var accessKey = config.AccessKey ?? throw new InvalidOperationException("S3 target requires AccessKey.");
        var region = config.Region ?? throw new InvalidOperationException("S3 target requires Region.");
        var secretKey = string.IsNullOrEmpty(config.EncryptedSecretKey)
            ? ""
            : CredentialProtector.Unprotect(config.EncryptedSecretKey);

        var s3Config = new AmazonS3Config
        {
            AuthenticationRegion = region,
        };
        if (!string.IsNullOrEmpty(config.Endpoint))
        {
            s3Config.ServiceURL = config.Endpoint;
            s3Config.ForcePathStyle = true;
        }

        _client = new AmazonS3Client(accessKey, secretKey, s3Config);
    }

    public async Task<bool> TestConnectionAsync(CancellationToken ct)
    {
        try
        {
            var exists = await BucketExistsAsync(ct);
            if (!exists)
                await _client.PutBucketAsync(new PutBucketRequest { BucketName = _bucket }, ct);
            return true;
        }
        catch
        {
            return false;
        }
    }

    private async Task<bool> BucketExistsAsync(CancellationToken ct)
    {
        try
        {
            await _client.GetBucketLocationAsync(new GetBucketLocationRequest { BucketName = _bucket }, ct);
            return true;
        }
        catch (AmazonS3Exception ex) when (ex.StatusCode == System.Net.HttpStatusCode.NotFound)
        {
            return false;
        }
    }

    public async Task UploadAsync(BackupFile file, IProgress<TransferProgress>? progress, CancellationToken ct)
    {
        ct.ThrowIfCancellationRequested();

        var key = RemoteKey(file.RelativePath);

        await using var source = File.OpenRead(file.FullPath);
        await _client.PutObjectAsync(new PutObjectRequest
        {
            BucketName = _bucket,
            Key = key,
            InputStream = source,
        }, ct);

        var head = await _client.GetObjectMetadataAsync(new GetObjectMetadataRequest
        {
            BucketName = _bucket,
            Key = key,
        }, ct);

        if (head.ContentLength != file.Size)
        {
            try { await _client.DeleteObjectAsync(new DeleteObjectRequest { BucketName = _bucket, Key = key }, CancellationToken.None); }
            catch { /* best effort cleanup */ }
            throw new IOException(
                $"Verifikation fehlgeschlagen für {file.RelativePath}: erwartet {file.Size} Bytes, erhalten {head.ContentLength}.");
        }
    }

    public async Task<IEnumerable<RemoteFileInfo>> ListExistingAsync(CancellationToken ct)
    {
        var response = await _client.ListObjectsV2Async(new ListObjectsV2Request
        {
            BucketName = _bucket,
            Prefix = _prefix,
        }, ct);

        var rootPrefix = _prefix.TrimEnd('/') + "/";
        return response.S3Objects.Select(o => new RemoteFileInfo(
            o.Key.StartsWith(rootPrefix, StringComparison.Ordinal) ? o.Key[rootPrefix.Length..] : o.Key,
            o.Size ?? 0));
    }

    public async Task DeleteAsync(string remotePath, CancellationToken ct)
    {
        var key = RemoteKey(remotePath);
        await _client.DeleteObjectAsync(new DeleteObjectRequest { BucketName = _bucket, Key = key }, ct);
    }

    public ValueTask DisposeAsync()
    {
        _client.Dispose();
        return ValueTask.CompletedTask;
    }

    // Same reasoning as FtpTarget/SftpTarget: plain string concatenation on forward slashes,
    // never Path.*.
    private string RemoteKey(string relativePath) =>
        string.IsNullOrEmpty(_prefix)
            ? relativePath.Replace('\\', '/')
            : string.Concat(_prefix.TrimEnd('/'), "/", relativePath.Replace('\\', '/'));
}
```
